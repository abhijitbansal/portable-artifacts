# make-demo Phase 0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fixture sites on loopback, a tested stepped clock and frame store, and a probe that says which of five public sites can be captured frame by frame.

**Architecture:** A new package folder `plugins/portable-artifacts/skills/make-demo` with no `SKILL.md` yet, so no installer, sync or skill test sees it. `scripts/lib/` holds code later phases keep (stepper, frame store). `test/feasibility/` holds the probe, which is a test tool and never runs in CI.

**Tech Stack:** Node 20+, `node:test`, Playwright 1.64.0 (Chromium), no other dependency.

**Spec:** `docs/superpowers/specs/2026-11-24-make-demo-design.md` (4.1, 6.5, 7, 9)

## Global Constraints

- Playwright pinned at `1.64.0`; `overrides` `{ "fast-uri": "3.1.9" }`; `"engines": { "node": ">=20" }`; `"type": "module"`.
- Viewport 1280 × 720, device scale 3, 30 fps.
- Tests use loopback fixtures only. No test visits a public site. Only `probe.mjs`, run by hand, does.
- The probe is `look` only: `goto`, `scroll`, `hover`, and `click` on a listed in-page control or plain link. It types nothing and submits nothing.
- One headless browser at a time: `pgrep -fl chrome-headless-shell` first; tests run with `--test-concurrency=1`.
- Functions under 50 lines, files under 400; no swallowed errors.
- Commit trailer, exactly: `Co-Authored-By: Claude <noreply@anthropic.com>`. Conventional subjects. No push. No version bump in this phase.

## Review Focus

1. A page that polls forever: settling must end at its cap and say `capped`, never hang. (Task 2)
2. A page that reads `Date.now()` and `performance.now()` together: both must move by the same step. (Task 2)
3. An animation that starts in the middle of a take, and an infinite one: the first ends at its end, the second keeps going. (Task 2)
4. A site that shows different content on each load: the mask must not turn a real difference into a pass; over half masked is `inconclusive`. (Task 3)
5. A site that answers with a bot check, a cookie wall or an error page: reported as such, never counted as steppable because both runs saw the same wall. (Task 3)

### Task 2: Stepped clock and frame store

**Files:**
- Create: `scripts/lib/stepper.mjs`, `scripts/lib/frames.mjs`, `scripts/lib/browser.mjs` (a small `launchBrowser()` and `liveBrowsers()`; same behaviour as make-motion's and `shared/shot.mjs`'s)
- Test: `test/stepper-browser.test.mjs`, `test/frames.test.mjs`

**Interfaces:**
- Consumes: `startSites` from Task 1.
- Produces:
  - `installStepper(page, { fps = 30 }): Promise<Stepper>`, called before `goto`. `Stepper`: `step(n = 1): Promise<void>` (moves page time n frames, then sets every running animation to that time), `now(): number` (ms of film time), `settle({ stillFrames = 6, maxFrames = 90, maxRealMs = 10000 }): Promise<{ frames: number, capped: boolean, reason: 'still' | 'frames' | 'time' }>`.
  - `scrollTo(page, y, seconds)`: starts an eased in-page scroll driven by `requestAnimationFrame`, so it works in both modes.
  - `frameStore(dir): { add(buffer): { index, file, repeated }, index(): string[], bytes(): number }`, files named `<sha256 first 16>.jpg`.

Approach: `page.clock.install({ time: 0 })`, `pauseAt` after load, `clock.runFor` a step; step sizes alternate so 30 steps add to exactly 1000 ms. Animations come from `document.getAnimations()`: pause when first seen, then set `currentTime` from its first-seen film time; past the end, `finish()`; infinite ones keep their time. "Still" means equal screenshot bytes for `stillFrames` steps with no request in flight.

### Task 3: Compare and probe

**Files:**
- Create: `test/feasibility/compare.mjs`, `test/feasibility/probe.mjs`, `test/feasibility/sites.json`
- Test: `test/feasibility-compare.test.mjs`, `test/feasibility-probe.test.mjs`

**Interfaces:**
- Consumes: `installStepper`, `scrollTo`, `frameStore`, `launchBrowser`, `liveBrowsers`, `startSites`; `readPng` (or the name it exports) from `../../../make-motion/scripts/v2/png.mjs`, in test code only.
- Produces:
  - `stableMask(a, b, { block = 24, tolerance = 6 }): { mask: Uint8Array, share: number }` over two RGB pictures of one size; a block is stable when its largest luma difference is at most `tolerance`; `share` is the stable share.
  - `maskedSsim(a, b, mask, { block = 24 }): number`, the mean block SSIM on luma over stable blocks (C1 = 6.5025, C2 = 58.5225).
  - `verdict({ ssims, shares, controlsEqual, newErrors, wall }): { verdict: 'steppable' | 'not-steppable' | 'inconclusive', why: string[] }`.
  - CLI: `node test/feasibility/probe.mjs <sites.json> --out <dir>` writes `results.json` and the PNGs, prints one line a site. Exit 0 when it ran, 2 for usage or a live browser.
- `sites.json` entry: `{ "name", "url", "steps": [{ "do": "scroll", "to", "seconds" } | { "do": "hover" | "click", "role", "name" }] }`.

Rule (spec, phase 0): after each step the settled stepped picture and the settled real-time picture match at SSIM at least 0.98 over blocks that are equal in two real-time runs; the control lists (role and name from `ariaSnapshot`) are equal; the stepped run has no page error the real-time runs lack. A stable share under 0.5 at any step is `inconclusive`. A wall (status 400 or above, or a title or heading matching `/verify you are human|access denied|captcha|just a moment|enable javascript/i`) is `not-steppable`, whatever the pictures say. `inconclusive` does not count toward three of five.

A site record also holds: seconds of wall time a second of film, bytes a second with repeats stored once and without, settle results, and requests that were not GET (count).

## Fix round 1 (after review 1, 2026-11-24)

Review 1 found that the probe could change a site and could call a page steppable when it was not. No full probe had run on a public site. Decisions, replacing the rule in Task 3 where they differ:

**Safety (findings A1 to A15).** `click` is removed from the probe, with `clickRefusal` and the danger list. Steps are `scroll` and `hover` only, so the five sites are tested on loading, scrolling and hovering; menus and tabs wait for phase 2's approved takes. In every run, on the context:
`serviceWorkers: 'block'`, `acceptDownloads: false`, popups closed and counted, permissions none. The page's own requests run while it loads. Once loaded, anything but GET, HEAD and OPTIONS is aborted and a new WebSocket is closed, for the rest of the run, whatever the step (`context.route`, `context.routeWebSocket` installed
before the first page, switched by phase). A top-level navigation after load is aborted. Counts and paths are kept for all runs by phase, sent and blocked apart. A blocked request to the site's own origin makes it `inconclusive`; to another origin it is a note. Wording everywhere: "sends nothing beyond what loading the page sends".

**Verdict (B1 to B14).** Three real-time runs and one stepped run.
- A block (12 px) is stable when the three real runs agree within 6 on every channel of every pixel. Under 0.5 stable is `inconclusive`.
- A stable block is wrong when more than 8 of its pixels differ by more than 24 on any channel from each real run. Any connected group of 2 wrong blocks, or one block with at least half its pixels wrong, is `not-steppable`, with the boxes in `why`. SSIM is reported, never judged.
- The whole body's accessible tree comes from `ariaSnapshotJSON`: roles, names, states and text as an ordered list with counts. Lines that differ among the real runs are left out; over 20% left out is `inconclusive`; any other difference is `not-steppable`.
- Page errors, console errors and failed requests are counted by kind, with ids and numbers stripped. A crash, a timeout or a missing control in the stepped run only is `not-steppable`; in a real run, `inconclusive`.
- Settled means still for 1 s of film or real time with nothing pending; caps are 8 s of both, and one hard deadline covers the whole call. If any run is capped the site is `inconclusive`, unless all four are capped with nothing pending and equal trees: then it is compared with `loops: true` in the record.
- Walls: the status of every main-frame response, final address equal in all runs, at least 20 characters of text or one control, body text and frame addresses against the wall patterns, consent walls among them when they cover half the viewport.
- A step that changed nothing in any run is recorded as `noEffect`.

**Stepper (C1 to C10).** Freeze the animation timeline over CDP (`Animation.setPlaybackRate` 0, a session for the page and one for each cross-origin frame), never call `pause()`. Each step: run the clock, then in every frame, for the document and every open shadow root, add `dt * playbackRate` to each running animation on the document timeline. Measured by the
orchestrator in scratch: iframe and shadow 990 of 990 ms, no drift in real time, page pause, replay, seek and rate 2 right; `reverse()` gave 165 where 99 was due, and a busy wait hung. So: `reverse()` must be fixed or listed as a limit with a test that pins what happens; each clock run races a deadline (2 s), and past it the context is closed and `step` throws a `StepTimeout`
that `settle` returns as `capped: true, reason: 'time'`. Detect and report, per run, what still runs in real time: workers, `video`, animated images, SMIL, Web Audio, closed shadow roots, smooth scrolling. Chromium virtual time was tried and rejected: it moves neither CSS animations nor `requestAnimationFrame`, and hangs on a busy wait. The header lists only limits a test shows.

**Files and CLI (D1 to D7).** Names start with a letter or digit, no duplicates; `http` or `https` without credentials; results written after each site; temp folders removed in `finally`; launch failure is exit 2 with one line; `liveBrowsers` fails closed and the browser it launches is the bundled one only (no Chrome fallback in this package yet); a frame name match compares bytes; `GET //` answers 400.

**Tests (E).** A fixture and a failing test first for each finding marked measured in A, B and C, `/random/` with near-equal grounds restored, `controlsEqual` and the write guard each with a mutation that turns a test red. D8: functions under 50 lines.

## Scope cut (owner, 2026-11-24, after review 2)

The owner: keep it simple, do not over-engineer, prevent the obvious failures such as explicit writes. Review 2 found more ways a hostile page could get past the guard or fool the verdict. They are not chased. This section wins over fix round 1 where they differ.

**Claim.** The probe visits five named, signed-out sites in a fresh browser. It scrolls and hovers. After load it blocks the explicit writes the browser lets it see (POST, PUT, PATCH, DELETE, form submits, beacons), new page sockets and top-level navigation. It does not claim more: workers, WebRTC, WebTransport, `fetchLater` and sockets opened during load are the site's own, as for any visitor.

- Reads a scroll or hover causes are allowed and listed (owner).
- A person judges. The tool says `no difference found`, `difference found` or `inconclusive` with its signals; the orchestrator looks at the stepped and real pictures of every step, and the report says "judged by eye" (owner). The bar stays 3 of 5.
- Grafana is reported `inconclusive` if the write block empties it (owner).

**Build (one commit each, a failing test first):**
1. `probe-guard.mjs`: `traffic.readsAfterLoad` holds `{ method, path }` of each request let through after `endLoad`. Header and `probe.mjs` header say the claim above.
2. `compare.mjs`, `probe.mjs`: the verdict words above replace `steppable` and `not-steppable`; `why` carries the share compared, and any blocked write or socket to another host.
3. `stepper.mjs` (C1): a cross-site frame that is off screen or hidden does not end the step: its wait races a native 250 ms timer.
4. `stepper.mjs` (V11): page errors in timers do not end a step whatever their text (a lost page is `page.isClosed()` or a crash), and an error's class prefix does not make it differ from real time.

Everything else in `review-2.md` is left, and a known limit. No third review round; the orchestrator reads the diff. Nothing else is added to the probe. It is a test tool and does not ship.

# make-demo phase 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A take folder from make-demo plays in make-motion as a new `walk` shot: the real frames, retimed to the words, with
camera stops, a drawn cursor, a lift and findings, in the `keynote` and `desk` looks.

**Architecture:** make-motion reads the take folder in Node before the page opens. The take is untrusted input, so a reader
checks it (`scripts/v2/take.mjs`). A `walk` preparer turns it into plain JSON for the page. The server serves its frames the
way it serves a video clip's decoded frames (`/clip/<k>/<n>`), but by the file names in `take.json`. A pure retime module maps
shot seconds to take frames and gives `buildTimeline` an optional per-shot minimum length. The kind draws the frame in the
`screen` kind's browser chrome. It adds camera layers for the stops, kind-internal cursor and ripple nodes, and a lift made
by cropping the settled frame.

**Tech Stack:** Node 20+, Playwright 1.64.0 (already pinned), make-motion's v2 engine. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-24-make-demo-design.md` sections 6.7, 6.8 and 10 item 5; hand-off
`docs/superpowers/plans/2026-11-26-make-demo-handoff-p3.md`; phase 2 plan `docs/superpowers/plans/2026-11-26-make-demo-p2.md`.

## The claim of this phase

1. Every picture a `walk` shot shows of the product is a frame of the take, drawn as stored. It is never redrawn, never
   upscaled past the frame's own pixels, and a lift crops the frame under it.
2. A take folder cannot make make-motion read, serve or decode anything except the frames named in its own `take.json`. Each
   frame is a regular JPEG or PNG file inside the take's `frames/` folder, inside the film's folder after links are
   followed, with the size the take claims. A take that breaks any rule is refused with the field that broke it.
3. Step n plays on sentence n (or its `at`). It runs at real speed with idle stretches cut. Its last frame holds until the
   next step starts. An action longer than its words stretches the shot. No existing film's timeline, frames or goldens change.
4. `keynote` and `desk` ship `walk` only after the look gate passes. Until then the kind stays parked in that look.
5. No frame of a signed-in take is opened by the model. make-motion's report says so for any film that plays one.

A finding outside this claim that is not an obvious failure goes to "Known limits".

## Owner's answers (2026-11-26)

- **Stretch.** A step starts at its sentence (or `at`). If the step before it, with its hold, ends later, it starts then.
  The shot lasts until the last step's hold ends. `buildTimeline` gains an optional per-shot minimum length. It is absent
  for every other kind, so existing timelines do not move.
- **Look gate with an independent reviewer.** Per look: a gate film, zero findings, and one fresh Opus look reviewer per
  round who sees only the sheets. At most two revision rounds. A look that still fails keeps `walk` parked and goes to the
  owner. Gate films use the committed signed-out fixture take only.
- **Measure text size in the take.** make-demo records `textPx` per step: the smallest visible font size inside the step's
  box, in CSS px, or null. `take.json` stays version 1; the field is optional.

## Review Focus

1. A `take.json` frame name that is a link to a file outside the take (`frames/abcd….jpg -> ~/.ssh/id_ed25519`), or a link
   that is swapped after the server starts: 404, nothing read (Tasks 2, 3).
2. A `take.json` of 200 MB, or one listing 10 million frames: refused before it is parsed or walked (Task 2).
3. A file named `.jpg` that holds a PNG, an SVG, HTML or a 30,000 × 30,000 JPEG header: refused at read with the frame's
   name (Task 2).
4. A step whose `settleFrame` is before its `startFrame`, past the last frame, or overlapping the step before: refused, not
   clamped (Task 2).
5. A 3840 × 2160 take played for 60 s: the page's frame cache stays bounded by pixels, not by count (Task 3).

### Task 2: make-motion: the take reader (the security core)

**Files:** create `scripts/v2/take.mjs`, `scripts/v2/prepare/walk.mjs`; modify `scripts/v2/prepare/index.mjs` (`PREPARERS.walk`);
tests `test/v2/take-reader.test.mjs`, `test/v2/helpers/synthetic-take.mjs` (writes tiny PNG takes with
`scripts/lib/png-write.mjs`, so unit tests need no browser).

**Interfaces:**
- Produces: `readTake(specDir, src, { owner }): Take`. It throws `SpecError([{ path: \`${owner}.src\` …, message }])` for a take
  the film must fix. `owner` is `shots[<i>]`. `Take` is:
  `{ src, dir, framesDir, names: string[], fps: 30, viewport: { width, height }, scale, width, height, signedIn: boolean,
  steps: [{ id, do, startIndex, actIndex, settledIndex, pointer: { x, y } | null, box: { x, y, width, height } | null,
  textPx: number | null }] }`. Indexes are 0-based into `names` (film frame f is `names[f - 1]`).
- Checks, in order. Each one is refused with the take field that broke it:
  1. `src` is relative, has no NUL, and resolves (realpath) to a folder inside `realpath(specDir)`. `take.json` is a regular
     file inside it, at most `TAKE_JSON_MAX` = 8 MiB by `stat`, checked before it is read.
  2. Parsed JSON, `version` 1, `fps` 30, `mode` `stepped`, `scale` an integer 1 to 3. `viewport` integers 320 to 1920 by 320
     to 1200. `signedIn` boolean. Any other root key is ignored.
  3. `frames`: an array of 1 to `MAX_FRAMES` = 6,000 strings, each `/^[0-9a-f]{16}\.(jpg|png)$/`. `steps`: 1 to
     `MAX_STEPS` = 200 entries. `id` matches `^[a-z][a-z0-9-]{0,39}$` and is unique.
  4. Per step: `startFrame <= actFrame <= settleFrame`, all integers in `1..frames.length`. `settledIndex === settleFrame - 1`,
     or `settledIndex` in range and greater than or equal to `actFrame - 1` (the take's own rule). Each step starts at or after
     the previous step's settled index. `pointer` and `box` numbers are finite and within the viewport grown by its own size.
     `textPx` is null or a number from 1 to 200.
  5. `frames/` resolves inside the take folder. Each distinct name, through `fileInside(framesDir, …)` from `server.mjs`, is a
     regular file of at most 16 MiB. Its first bytes match its extension (JPEG `FF D8 FF`, PNG signature). Its header size
     (JPEG SOF, PNG IHDR) equals `viewport × scale` on both sides. The distinct files together weigh at most 3 GiB.
- `prepareWalk(shot, { filmDir, index })` returns `{ data, problems }`. `data` is the take minus `dir` and `framesDir`, plus
  `distinct`, the count of distinct names. Paths never go to the page.

- [ ] **Step 1: failing tests**, one per check, on synthetic takes in a temp folder: an absolute `src`, `../x`, and a link
  to a folder outside; a take.json of 8 MiB + 1 (by `truncate`, never parsed); `version` 2; 6,001 frames; a name with `/`, with
  `..`, and with uppercase; a frame link to a file outside `frames/`; a `.jpg` holding PNG bytes; a PNG whose IHDR says 30,000
  wide; a frame of the wrong size; a step with `settleFrame` 0, one past the end, one before its `startFrame`, and one that
  starts inside the previous step; a duplicate id; `textPx` 0. Each is refused with its field in the message. A good take
  returns `names`, `steps` with 0-based indexes and `signedIn`. `prepareFilm` of a film with a walk shot puts the data under
  the shot id. The committed `walk-take/` reads clean.

### Task 4: make-motion: retime and the stretch

**Files:** create `engine/kinds/walk-time.mjs`; modify `engine/script/timing.mjs` (`buildTimeline` option `prepared`, and a
kind hook), `scripts/v2/pipeline.mjs:69`, `scripts/v2/run.mjs` `timelineFor` (pass `prepared`); test
`test/v2/walk-time.test.mjs`, an addition to the timing tests.

**Interfaces:**
- Consumes: the preparer's `data` (`steps`, `names`, `fps`).
- Constants: `IDLE_RUN` = 15 frames, `IDLE_KEEP` = 6, `GLIDE` = 10, `HOLD_MIN` = 0.5 s.
- `keptFrames(data, step): number[]`: the indexes `startIndex..settledIndex`. A run of more than `IDLE_RUN` equal names
  shrinks to its first `IDLE_KEEP` frames, except the `GLIDE` frames before `actIndex`, which are always kept (the cursor
  travels over them).
- `walkPlan(shot, timing, data, { lifts }): { steps: [{ id, start, act, end, until }], end }`, in shot seconds. Step i's
  anchor is `resolveAnchor(step.at, timing)` when it has `at`, else sentence i's start, else (no say) 0.
  `start_i = max(anchor_i, until_{i-1})`; `act_i = start_i + (kept frames before actIndex) / fps`;
  `end_i = start_i + kept.length / fps`; `until_i = end_i + max(HOLD_MIN, liftSeconds_i)`, where `liftSeconds_i` is the lift's
  `at - end_i` plus its 0.8 s of moves plus its `hold` (0 with no lift). Before step 1 starts, the walk shows
  `steps[0].startIndex`.
- `walkFrameTrack(plan, data)`: a `track` whose value is the take frame index: one linear run per run of kept frames, a jump
  (two keys at one t) at each cut, flat over each hold. It is the value `props.video` frames read (`frameIndexOf`).
- Kind hook `minSeconds(shot, { sentences, words, prepared }): number | undefined`; `walk` returns `walkPlan(...).end`.
  `buildTimeline(film, { …, prepared = {} })`: after `timedShot`, `seconds = max(seconds, kind.minSeconds?.(…) ?? 0)`, for the
  estimate and per-shot voice. The recording path is untouched (the kind refuses it). `pipeline.mjs` and `run.mjs` pass
  `prepared`.
- Validation errors, at the shot's path: some steps lack `at` and the sentence count is not the step count ("6 steps, 5
  sentences: give each step a sentence or an at"); a walk step id not in the take; steps out of take order.

- [ ] **Step 1: failing tests**, pure, on hand-made `data`. A 40-frame still run shrinks to 6; the glide's 10 frames before an
  act survive inside a still run. Three steps on three sentences start on them. A step whose action outruns its sentence
  pushes the next step to `until`, and the shot's `minSeconds` grows to the last `until`. A say-less shot plays the steps back
  to back. The frame track at `start_i` is `startIndex`, at `end_i` is `settledIndex`, and flat until `start_{i+1}`.
  `buildTimeline` of `gate-desk.json` and every other example film is deep-equal before and after: no existing shot moves.
  The count-mismatch error names both counts.
- [ ] **Step 2:** red. **Step 3:** implement. **Step 4:** green, plus the whole timing and anchors tests.

### Task 5: make-motion: the `walk` kind

**Files:** create `engine/kinds/walk.mjs`, `walk-layout.mjs`, `walk-camera.mjs`, `walk-cursor.mjs`, `walk-review.mjs`;
modify `engine/kinds/index.mjs`, `engine/kinds/screen-layout.mjs` (export `roomOf`, `fitFramed`, `nativeZoom`; no change in
behaviour), `engine/looks/keynote.mjs` and `desk.mjs` (`kinds.walk` with `experimental: true`), `scripts/v2/review.mjs` only if
the review hook does not yet get `prepared` and the timeline; tests `test/v2/walk-kind.test.mjs`, `test/v2/walk-browser.test.mjs`.

**Interfaces:**
- Schema: `src` (string, the take folder), `steps` (1 to 40 `{ id, at? }`), `frame` (`browser` default, `window`, `none`),
  `stops` (0 to 12 `{ to: 'whole' | 'step:<id>', at? }`), `lift` (0 to 4 `{ step, at? }`), `title` (as `screen`), `on` (today's
  devices; targets `screen` and `step:<id>`). `srcFields: []`, `lookData: true`, `prepared: true`, `minSeconds` from Task 4,
  `eventDevices: ['zoom']` (one event per stop that lands on a step).
- Refused in `validate`: a tall canvas, a recording-narrated film, and a look without `kinds.walk` (`kindSupportProblems`).
- Layout: the screen kind's room and fit at `wideShare`, with `frameNodes` for the chrome. The picture is one `image` node
  with `props.video: { count }` and the `walkFrameTrack` as its `frame` track. A page point p maps to
  `[ix + p.x / viewport.width * iw, iy + p.y / viewport.height * ih]`, and boxes the same way.
- Camera (`walk-camera.mjs`): one layer for the stops, plus the look's `defaultCamera`. A `step:<id>` stop lands at that
  step's `start` unless it has `at`. A `whole` stop with no `at` lands `HOLD_MIN` after the previous stop's step ends; a
  first `whole` stop is the shot start. Each move takes 0.8 s with the in-out cubic ease from `engine/time/ease.mjs`. The
  target is `pushLayer(ctx, box, at, { max: nativeZoom(picture, image) })[1]`. A move never starts inside a step's
  `[end, end + HOLD_MIN)` or during a `scroll` step's action; it moves later. A stop that cannot land before the next one
  starts moving is dropped and is a finding.
- Cursor (`walk-cursor.mjs`): kind-internal `path` nodes, `fixed: true`, so the camera does not scale them. Size is 5% of
  the canvas height, an arrow in the look's ink with a paper keyline. Its position is the page pointer through the image map
  and then `pointThroughCamera` with the shot's own camera, keyed once per film frame. It travels over the `GLIDE` frames
  before `act` on one quadratic curve from the previous pointer. At `act` it dips to scale 0.9 for 0.12 s. A `click` adds a
  ripple: a ring in the look's accent, from 0.5 to 2 times the cursor size over 0.4 s. The cursor is clamped inside the
  frame. It is off until the first step with a pointer; a step with no box keeps it where it was.
- Lift: from `at` (default 0.5 s after the step's `end`): the step's box cropped from `settledIndex` (an image node with
  `props.video`, a constant frame track, and `clip` the box in frame pixels). It scales to the look's `lift.scale` over 0.4 s
  on the look's elevated shadow, holds `lift.hold`, and returns over 0.4 s. The rest dims with the `focus` device. Its
  seconds feed `walkPlan`'s `until`.
- `kinds.walk` look data (keynote and desk): the frame keys `frameNodes` reads (copied from each look's `kinds.screen`),
  `wideShare`, `lift: { scale, hold }`, `experimental: true`.
- Findings (`walk-review.mjs`, through the kind's `review` hook):
  - "step `<id>`: page text of `<textPx>` px shows at `<n>` px at its stop; push closer or lift it". This fires when
    `textPx × (iw / viewport.width) × zoom × (1080 / canvas.h) < 26`, at a `step:` stop with a known `textPx`.
  - "stop `<n>` wants `<z>`x; the take carries `<cap>`x".
  - "step `<id>`'s action leaves the frame". This fires when the box, or the pointer at `act`, is outside the camera's
    visible rect during `[start, end]`.
  - "take step `<id>` is not in this shot's steps: the film jumps across it".
  - "stop `<n>` has no room to move".
- Notice: a film with a walk shot whose take has `signedIn` true prints in make.mjs's report (text and `--json`): `shot "<id>"
  plays a signed-in take: its frames, sheets and film are the user's to look at; do not open them.`

- [ ] **Step 1: failing tests.** Pure: the schema accepts the example and refuses a tall canvas, a recorded film, `pop`,
  and a stop to an unknown step. The cursor's position at `act` equals the step pointer through the image map and the
  camera. The cursor stays inside the frame at full push on a corner step. Each finding fires on a fixture built to trip it
  and stays silent on the committed take. Expanding a `screen` shot is deep-equal before and after the screen-layout export

- [ ] **Step 2:** red. **Step 3:** implement. **Step 4:** green, plus the whole v2 suite in the background (one browser).

## How it is built

Six builder dispatches, one per task 1 to 6, in order, Sonnet at high effort. Tasks 2 and 4 are pure and could run in
parallel, but Task 4 consumes Task 2's data shape. Serial keeps it simple. The main session reviews each diff, reruns the
tests, commits and pushes. The look gate adds up to two Opus look reviewers per round (two rounds at most) and one Sonnet
revision dispatch per failed look per round. Then one Opus security reviewer. No other agents.

## Known limits, to be stated

- 16:9 only. Not in a film narrated by one recording. Looks other than keynote and desk refuse `walk`.
- No captured parts: a lift is a crop of the frame, so it is no sharper than the frame. `part:` stops are not built.
- Marks are today's devices on a step's whole box, not on one number inside it.
- Idle means identical frame files. A blinking caret or a spinner makes a "still" screen play at real speed.
- `textPx` is the smallest visible text in the step's box, main frame only. Text in a canvas, an image or a cross-origin frame
  is not measured.
- A take's frames are served as stored. A covered value shows as its grey cover box at any zoom.
- The reader checks a frame's header and its first bytes, not that the whole image decodes. A corrupt frame fails in the page
  with its name.
